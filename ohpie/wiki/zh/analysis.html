数据分析与成果

持久化内核、笔记本标准、绘图与成果登记。

分析在 OhPie 里不是"生成一段代码让你去跑"，而是在本地内核里真的跑，并把代码、输出和产物留在工作区。

内核与环境

  • Python 与 R 都走本机解释器，不需要额外安装运行时。
  • 内核跨单元、跨轮次保留变量：上一轮建的 DataFrame，这一轮还能接着用。
  • 项目可以指定自己的虚拟环境或 renv，避免不同课题的依赖互相污染。
  • 环境缺失时如实报错，不会假装跑过。

笔记本标准

每一次分析都产出成对的文件：

.ipynb 给机器（可以继续运行、可以导出），.qmd 给人（能读、能渲染成报告）。两者内容一致，不各自演化。

绘图

发表级图形按期刊惯例来：尺寸、字号、配色、面板标注都要能直接进排版。常用的两个动作是 Nature标准统计核验（统计量、检验选择、报告方式）与 顶刊双栏复合面板图（多面板排版）。

图存在 experiments/4_results/figures/，表存在 tables/。文件名用能读懂的英文短名，不要 plot1_final_v3.png。

成果与登记

保存的成果进入画布的成果面板，并可以附带实验凭证：产出它的代码、声明的输入、运行环境与内容指纹。凭证汇入 experiments/4_results/passport.yaml。

导出

  • Notebook 导出 .ipynb 与 .qmd。
  • 表格导出 CSV / TSV。
  • 图导出 PNG / PDF / SVG，按投稿要求选。

复现的最小条件

一次能复现的分析需要四样东西同时存在：原始数据（未改）、清洗代码、分析代码、依赖版本。少任何一样，别人（或半年后的你）就只能重做，不能复现。

内核里跑通，不等于结论正确。执行、登记、验证是三件事，见实验凭证。
