数据分析与成果

持久化内核、笔记本标准、绘图与成果登记。

分析在 OhPie 里不是"生成一段代码让你去跑"，而是在本地内核里真的跑，并把代码、输出和产物留在工作区。

内核与环境

  • Python 与 R 都走本机解释器，不需要额外安装运行时。
  • 内核跨单元、跨轮次保留变量：上一轮建的 DataFrame，这一轮还能接着用。
  • 项目可以指定自己的虚拟环境或 renv，避免不同课题的依赖互相污染。
  • 环境缺失时如实报错，不会假装跑过。

笔记本标准

每一次分析都产出成对的文件：

.ipynb 给机器（可以继续运行、可以导出），.qmd 给人（能读、能渲染成报告）。两者内容一致，不各自演化。

绘图

发表级图形按期刊惯例来：尺寸、字号、配色、面板标注都要能直接进排版。常用的两个动作是 Nature标准统计核验（统计量、检验选择、报告方式）与 顶刊双栏复合面板图（多面板排版）。

图存在 experiments/4_results/figures/，表存在 tables/。文件名用能读懂的英文短名，不要 plot1_final_v3.png。

成果与登记

保存的成果进入画布的成果面板，并可以附带实验凭证：产出它的代码、声明的输入、运行环境与内容指纹。凭证汇入 experiments/4_results/passport.yaml。

导出

  • Notebook 导出 .ipynb 与 .qmd。
  • 表格导出 CSV / TSV。
  • 图导出 PNG / PDF / SVG，按投稿要求选。

环境准备

需要单独环境时，在项目目录里建，然后指向它：

环境目录不要进版本库：.venv/、renv/library/ 写进 .gitignore，提交 requirements.txt / renv.lock 即可。

常见的三种跑法

场景 怎么问 产物落在哪
第一次接触数据 “先看结构、缺失与异常，不要动数据” experiments/5_report/ 里的探查记录
正式分析 “按这份方案跑，结果写到 4_results/” notebook + 图表 + 凭证
补充分析（审稿要求） “只加这个亚组分析，不改主分析” 新增一个编号 notebook，不动旧文件

第三条纪律最重要：补充分析新开文件，不要在原 notebook 上改。审稿人要看“改了什么”。

统计报告的最小要求

一个数值报告至少带上：效应量、不确定度（CI 或 SE）、样本量、检验方法。只写 p 值在多数期刊会被要求补。

要素 写法
效应量 均值差 / HR / OR / β，带单位
不确定性 95% CI
样本量 每组 n，以及缺失情况
方法 检验名与是否校正多重比较
预注册 有就写，没有就说明是探索性

常见错误

报错 原因 处理
ModuleNotFoundError: No module named 'pandas' 跑在系统解释器而不是项目环境 确认内核指向 .venv，或在该环境里装
there is no package called 'DESeq2' R 包未装 BiocManager::install("DESeq2")
内核重启后变量没了 进程退出 变量不落盘，从上游单元重跑
中文路径报错 编码 路径改 ASCII，或显式 encoding="utf-8"
图里的中文变方块 字体缺失 指定已装中文字体，或图注用英文

图表速查

参数 单栅栏 双栅栏 依据
宽度 85 mm 180 mm 期刊排版要求
字号 7–8 pt 7–8 pt 缩放后仍可读
分辨率 300 dpi 300 dpi 位图投稿下限
线宽 0.5–0.75 pt 0.5–0.75 pt 印刷不丢失
配色 色盲友好、灰度可区分 同左 打印与可达性

导出先用矢量（PDF/SVG），期刊要位图时再给 300 dpi 以上的 PNG/TIFF。

复现的最小条件

一次能复现的分析需要四样东西同时存在：原始数据（未改）、清洗代码、分析代码、依赖版本。少任何一样，别人（或半年后的你）就只能重做，不能复现。

内核里跑通，不等于结论正确。执行、登记、验证是三件事，见实验凭证。
