对话与工具

一轮对话包含什么、工具权限怎么给、长对话怎么收。

一次提问不是一次文本生成。OhPie 把模型的思考、工具调用、工具结果和最终回答都展开在同一条消息流里，所以你能看见"这个数字是怎么来的"，而不只是结论。

一轮对话里发生什么

  1. 思考：模型先想，思考块默认收起，可展开。
  2. 工具调用：每次调用一张卡片，显示工具名、参数与状态。
  3. 工具结果：文件内容、命令输出、搜索结果，失败会明确标出。
  4. 写入：改动落在工作区里的真实文件上，可以对比、可以回滚。
  5. 回答：最后才是给你看的那段话。

引用工作区文件

在输入框敲 @ 会打开文件索引，把文件引用进当前这一轮。引用的是路径而不是副本：模型读的是磁盘上那份，改的也是那一份。

对话里出现的文件路径也可以点击，直接在右侧画布打开。

工具权限

输入框上方可以切换工具预设。给的权限越大，能做的事越多，风险也越大：

预设 开放的工具 适用场景
Configured 跟随设置里的逐项开关 想自定义时
None 无 纯对话，不碰文件
Read only read grep find ls 只读审查、代码讲解
Default read bash edit write 日常分析
Full 上面全部，加上 grep find ls 需要检索与批量改动

四种好用的请求写法

模式 怎么写 为什么有效
指明产物位置 "把清洗结果写到 experiments/2_cleaned_data/" 避免文件落在奇怪的地方
先要计划再执行 "先给我分析方案，等我确认后再跑" 把错误拦在花钱之前
要求回指文件 "每个结论后面标出它出自哪份文件的哪一段" 可核对、可复制
要求说明缺项 "缺什么就直说，不要补全" 比看起来完整更有用

反例：“帮我分析一下这个数据”——不指明变量、终点和输出位置，结果只能靠猜。

怎么读工具卡片

工具卡片不是装饰，快速瞄三个地方就能判断这轮靠不靠谱：

  • 路径：改动的是不是你期望的那个文件。
  • 退出状态：命令失败时不要相信后面的结论。
  • 截断标记：输出被截断时，后面的推断可能建立在半个结果上。

发现不对，直接停下来纠正，比让它一路往下跑再收拾便宜。

模型与推理强度

模型选择器同时决定两件事：用哪个模型，以及推理强度。可用档位由模型目录提供，切换模型会重置为它支持的默认档。同一段对话里换模型是允许的，但换过之后的行为差异要自己留意。

附件与图片

图片可以粘贴或拖入，随消息一起发送，用于读图、读表截图、对照示意图。附件有数量与体积上限，超出时会直接拒绝而不是静默截断。

长对话

上下文快满时，会话会被压缩成摘要，之前的完整内容仍保留在 .jsonl 里。压缩之后模型看到的是摘要，不是你原来的措辞——需要精确复述时，重新引用文件比依赖记忆可靠。

生成失败或网络中断会显示重试提示，重试沿用同一轮输入。不要在一个失败轮次上继续追加问题，先让它重试或停止。
