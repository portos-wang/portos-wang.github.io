MCP 服务

全局与项目两套连接、测试、登录、信任与工具暴露方式。

MCP 是 OhPie 接入外部工具的唯一入口：文献数据库、生信服务、内部系统都走它。连接本身属于配置，能不能用取决于服务是否可达、凭据是否齐全。

两个作用域

作用域 文件 谁在用
全局 ~/.ohpie/mcp.json 所有工作区
项目 <workspace>/.ohpie/mcp.json 这个课题

同名时项目定义覆盖全局。把只在某个课题需要的服务放进项目作用域，换项目就不会误连。

添加一个服务

  1. 设置 → MCP → 添加，粘贴配置（支持常见客户端格式），或手动选择 stdio / HTTP。
  2. 选择作用域，检查解析结果后再保存。
  3. 点 Test，确认真实连接、暴露的工具和所需凭据。
  4. 需要授权的服务走 Sign in，在浏览器完成 OAuth。

stdio 服务写 command + args + 可选 env；远程服务写 url。命令必须能从 OhPie 进程解析到——桌面应用没继承新 PATH 时，填绝对路径。

工具暴露方式

一个工具很多的服务，一次把全部工具声明进对话会挤掉上下文。两种处理方式：

  • deferred：工具按需发现，模型先看到服务，需要时再列工具。
  • code mode：模型写代码调用工具，而不是逐个工具调用。

两者都属于连接配置，不是"高级选项"；服务工具超过十几个时建议从一开始就设成 deferred。

信任

项目作用域的 MCP 配置来自仓库本身，因此需要信任确认：打开一个陌生工作区时，OhPie 不会自动运行它 .ohpie/mcp.json 里定义的命令。确认过的项目会记住这个决定。

凭据

  • 服务自己的密钥写在连接的 env 或认证头里。
  • 科研数据库的密钥放在设置 → 凭据，由内置服务自动取用。
  • 显式 env 优先于继承值。

环境变量优先级

从高到低：

  1. 连接里显式写的 env
  2. 设置 → 凭据 里同名的变量
  3. 应用进程自身环境（很少用，容易被其他软件污染）

排查"为什么服务收到的 key 不对"时，按这个顺序看。

常见错误对照

报错 含义 处理
ENOENT / command not found 命令找不到 填绝对路径，或修 PATH
ECONNREFUSED HTTP 服务没起 先在外部启动服务
401 / 403 凭据缺失或过期 补 env 或重新登录
工具列表为空 服务启动成功但没注册工具 看服务自身日志与版本
超时 服务启动慢或网络 提高超时，或换本地部署

排错顺序

  1. 设置 → MCP → Test 看连接本身是否通。
  2. 看服务返回的错误：命令找不到、超时、401、工具名为空，各自对应不同问题。
  3. 检查命令路径与 PATH（stdio）、端口与地址（HTTP）。
  4. 检查凭据是否在正确的层：连接 env 还是全局凭据。
  5. 换一个最小请求验证，不要一上来就问复杂问题。

连接成功只说明握手成功。工具能不能给出你要的答案，取决于服务本身的数据与方法——见生物信息 MCP 的边界说明。
