扩展与子代理

技能与插件的安装、更新与作用域，以及子代理开关和 profile。

技能包提供方法与检查清单，插件提供工具与界面扩展。两者都从全局和项目两级发现，同名时项目优先。

技能

操作 在哪里 说明
安装 设置 → 技能 → 安装 从技能市场或 npm 源安装
搜索 设置 → 技能 → 搜索 按关键词查外部技能
查看 技能详情 读 SKILL.md 全文再决定是否信任
更新 设置 → 技能 → 检查更新 按来源比对版本
启用/停用 技能列表 停用只是不加载，不删除文件

内置的 25 个技能包随应用提供，首次安装时播种到 ~/.ohpie/skills/。它们可以被覆盖：在项目里放同名技能，项目版本生效。

插件

插件是带工具的 npm 包或本地扩展。安装后在会话里按需加载，工具通过 tool_search 发现，不必每轮都声明。

保留内置插件与仓库插件的区别：builtin-plugins/ 是随应用分发的，~/.ohpie/plugins/ 是你安装的。打包版启动时会刷新带基线的内置副本，同时保留用户改动。

更新原则

  • 更新前先看变更内容，尤其是技能包的方法论部分。
  • 本地修改过的技能，更新会走三方合并；冲突时保留三方文件，不强制覆盖。
  • 内置组件的版本更新走 maintain 流程，见构建与维护。

子代理

子代理把一段独立任务丢给另一个会话去跑，跑完把结果与完整对话交回来。

设置 作用
内置子代理开关 全局启用/停用内置子代理
Profile 为不同任务预设模型、提示与工具范围
主对话摘要 子代理结果以卡片形式回到主对话
完整对话 在画布里打开子代理记录

用一个子代理做"读十篇文献并列出方法差异"这类任务，比在主对话里连续追问更省上下文，也更容易复核——你能读到它到底做了什么。

停用子代理不会让已有记录消失。历史记录仍然可以打开，只是不再创建新的子代理会话。
