发布与更新

从版本号到公开更新清单，一次 Windows 发版要碰的五处地方。

OhPie 的发版是本地完成的：本机打包、本机校验、手动上传安装包、手动更新公开清单。仓库里虽然有 .github/workflows/release.yml，但当前只作为参考保留（Actions 计费未恢复前，打 tag 触发的构建会失败）。

一次发版涉及五处

位置 改什么 谁读它
package.json / package-lock.json 版本号 打包产物、resources/app/package.json
Git tag vX.Y.Z 标记发布提交 你、GitHub Release
docs/releases/vX.Y.Z.md 人读的发版说明 用户、更新页
GitHub Release 安装包、校验和、blockmap 下载用户
docs/releases/site/latest.json + 公开 Pages 应用检查更新的唯一来源 已安装的 OhPie

五处只要有一处没跟上，就会出现"新版本发了但用户看不到"或"提示有新版但下载 404"。

发布前

  1. 工作区干净，HEAD 与 origin/main 一致；只包含本次要发的改动。
  2. 在独立 worktree 中打包，不要用正在跑开发服务的目录。
  3. 下面的检查全部通过，且目标 tag 未被占用。
  4. 把计划发布的内容写进 docs/releases/vX.Y.Z.md，格式沿用上一版：主要更新 / 运行时与兼容性 / 下载与校验 / 上游基线。

五步流程

1. 定版本号

两条命令都不创建 Git tag：tag 要打在包含说明文件的发布提交上，而不是提前打。

2. 提交、打 tag、推送

用命名 tag 推送，不要 git push --tags：这份检出里可能还有上游标签。

3. 打包

产物在 dist/：OhPie Setup X.Y.Z.exe、便携目录 win-unpacked/，以及 .blockmap。

打包后确认两件事：安装包文件名带正确版本；dist/win-unpacked/resources/app/package.json 里的 version 与本次一致。

4. 校验与上传

--generate-notes 生成的是提交摘要，不能替代 docs/releases/vX.Y.Z.md 里的人读说明。

5. 更新公开清单

在 portos-wang.github.io 里提交并推送，Pages 自动发布。清单地址：

index.html（更新说明页）只在改版式时才需要跟新；内容由 latest.json 渲染。

打包环境的硬性要求

  • 不要在开发服务运行时执行 next build：两者共用 .next/，会互相破坏。
  • 用独立 worktree，配私有 build profile 与硬链接依赖副本；Turbopack 会拒绝指向 worktree 外的依赖 junction。
  • 冒烟测试必须在产物上跑，而不是在源码目录：

它检查启动、品牌身份、端口冲突、目录搬移与干净退出。

应用侧怎么看到更新

  • 已安装的 OhPie 每 12 小时拉一次清单，5 秒超时。
  • 清单 version 大于当前版本时，新会话页的版本行显示 → vX.Y.Z ↗，链接指向更新说明页对应锚点。
  • 清单缺失或不可达时静默跳过——不会弹错误，也不会显示过期提示。

出问题怎么办

情况 处理
打包失败 先确认不在开发 checkout 里；再确认依赖副本是硬链接而不是 junction
传错附件 删除该资产重新上传，不要重建同名 tag
说明写错 改 docs/releases/vX.Y.Z.md 与 latest.json 并重新提交；不要动已发布的安装包
版本已发出但有严重缺陷 发 X.Y.Z+1 补丁版，不要覆盖旧安装包或移动 tag
清单指错版本 修正 latest.json 并推送；应用下次轮询即恢复

已发布的 tag 与安装包视为不可变。修正靠新版本，不靠覆盖——否则校验和与用户手里的文件对不上。

发布检查清单

  • package.json 与 package-lock.json 版本一致
  • tag 打在包含说明文件的提交上
  • 类型检查、lint、测试通过并记录结果
  • 打包在独立 worktree 完成
  • 安装包文件名与 resources/app/package.json 版本一致
  • .sha256 与 .blockmap 一并上传
  • docs/releases/vX.Y.Z.md 已提交
  • latest.json 的 version、date、notes 已更新并保留历史
  • 公开仓库已推送，清单 URL 返回 200
  • 在旧版本应用里点到"有新版本"，链接可打开

不要做的事

  • 不要用 npm run release：那是上游 npm 发布脚本，不是 OhPie 的 Windows 发版入口。
  • 不要 git push --tags：会连带推上游标签。
  • 不要在开发 checkout 里 npm run build。
  • 不要把未脱敏的日志、本地绝对路径、私有服务地址写进发版说明。
