生物信息 MCP

ToolUniverse 与 BioMCP 作为外部 MCP 服务运行，OhPie 负责对话、发现与文件画布。

OhPie 不内嵌生信分析流水线。它通过 MCP 客户端调用 ToolUniverse 与 BioMCP，数据库、方法、任务状态和答案都由这些服务负责。OhPie 提供的是对话、工具发现、连接管理，以及展示返回结果的文件画布。

这条边界是刻意的。当一次查询没有返回时，值得追问的是哪个服务工具跑了、用了哪些标识符和哪种背景，而不是本机哪个表单填错了。

Windows 安装器准备了什么

安装完成前，安装器会联网获取 Puppeteer、ToolUniverse、BioMCP，并为它们准备独立的 Node.js/npm 与 Python。Puppeteer 优先复用本机已装的 Chrome 或 Edge，找不到浏览器时才下载。服务环境位于 ~/.ohpie/mcp/，下载失败会自动退避重试，日志写在同一目录的 install.log。

全新安装完成后，打开 设置 → MCP → 全局，对三个服务分别执行 测试连接。升级会保留已有配置、禁用状态与已记录的移除操作。

凭据

打开 设置 → 凭据，填写需要的 API Key 与联系邮箱，点击 保存并同步。内置的 w77-nfsc-pipeline、本地 ToolUniverse 与 BioMCP 会自动取用这些凭据——不必再编辑 .env，也不用在 mcp.json 里手写环境变量块。

PubMed（NCBI）、OpenAlex 与 Semantic Scholar 已有条目。其他数据库点 添加自定义凭据：

凭据名称 会设置的变量
NCI NCI_API_KEY
DisGeNET DISGENET_API_KEY
UMLS UMLS_API_KEY
OpenFDA OPENFDA_API_KEY
AlphaGenome ALPHAGENOME_API_KEY
OncoKB ONCOKB_TOKEN、ONCOKB_API_KEY
ORCID ORCID_ACCESS_TOKEN

其他英文名称会自动生成 <名称>_API_KEY 与 <名称>_EMAIL。服务要求别的变量名时，在同一表单的可选 API Key / 邮箱变量字段里填写。清空或删除凭据会在下一次发消息时撤销对应的环境变量。

已有 MCP 配置中的显式 env 值优先于继承值。自行部署的 HTTP MCP 可以在认证请求头中引用凭据变量，但远程服务背后的数据库凭据由该服务端管理。

添加或自定义服务

  1. 在 OhPie 之外安装或部署服务。ToolUniverse 官方给出 uvx tooluniverse；BioMCP 官方给出 uv tool install biomcp-cli，随后 biomcp serve。
  2. 打开 设置 → MCP → 添加，粘贴配置，选择全局或项目作用域，检查解析结果后保存。
  3. 对每个条目执行 Test，确认真实连接、暴露的工具和所需凭据。项目作用域沿用既有信任规则。
  4. 回到对话提出研究任务，智能体按服务当前的工具 schema 发现并调用能力。

命令必须能从 OhPie 进程解析到。桌面应用没有继承到刚改过的 PATH 时，填写已安装命令的绝对路径，然后重新测试。

对话示例

  • "通过 BioMCP 查询 BRAF V600E 的 ClinVar 记录及相关研究，给出来源链接，并说明返回范围。"
  • "通过 ToolUniverse 检索这个主题的公开数据集，先列出候选研究及其真实文件信息，再决定是否下载。"
  • "在 ToolUniverse 里找富集分析工具，确认它支持小鼠、自定义背景和我需要的校正方法，满足后再调用。"

查询成功只代表那一次调用返回了那个结果。无结果、失败、截断与完整性未知分别说明；方法、物种、标识符、背景与校正按服务自身的语义报告。

OhPie 仍然在本地做什么

通用 Python/R 内核、笔记本导出、CSV/TSV 表格、XLSX 工作表清单与成果画布继续可用，处理的是服务写进工作区的文件。OhPie 不再提供第一代内置管线：没有内置的 count 导入、QC/DE/ORA 表单、分析队列或依赖准备。新分析使用服务的工具与状态接口。

决策记录见 ADR 0014；内置服务版本如何更新与验证，见构建与维护。
