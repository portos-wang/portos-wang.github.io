Desktop and updates

Window behaviour, tray, ports, update checks and what works offline.

OhPie is a desktop application, not a web page: it manages its own window, tray, backend processes and update checks. Knowing these behaviours explains most "why did it not quit the way I expected".

Single instance and tray

  • Only one instance runs at a time; launching again brings the existing window forward.
  • Closing the window either minimises to the tray or quits, depending on your choice.
  • Quit from the tray stops the backend processes the app owns (local server, kernel, terminals).
  • Minimising to the tray does not stop work: a running analysis continues.

Ports and the server record

The launcher picks a free port and writes the current record to .next/ohpie-server.json. That file is the single source of truth for "where is the healthy server for this checkout":

  • An occupied port falls back to another available port.
  • Fix the port with OHPIE_PORT when you need to.
  • Changing the port needs no configuration edits; the record updates.

Updates

The desktop build checks a public update manifest, shows a notice on the version line when something newer exists, and links to the release notes. It checks OhPie's own releases, never the upstream project.

Installers are distributed by the author directly, not through an app store.

Window state

Window size, panel widths and tab state are remembered. The drag handle between chat and canvas is clamped, so a panel cannot be collapsed into a sliver by accident.

What works offline

Capability Needs network?
Opening, reading and searching local files No
Local Python / R analysis No
Cached sessions and history No
Model calls Yes, unless you run a local model
Literature search, MCP services Yes
Update checks Yes

Where the data is

  • Application and runtime: the install directory; removing it deletes them.
  • Configuration, credentials, global skills: ~/.ohpie/.
  • Sessions and project resources: each workspace's .ohpie/.
  • Service environments (Puppeteer / ToolUniverse / BioMCP): ~/.ohpie/mcp/.

Back these up separately. Uninstalling does not delete ~/.ohpie/, and it never touches your workspaces.

Closing the window, quitting from the tray, and uninstalling affect progressively more. When unsure, look at the tray menu before deciding.
