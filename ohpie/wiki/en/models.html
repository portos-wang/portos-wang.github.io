Models and providers

Sign in or paste a key, choose which models show up, set the default and the reasoning level.

Model configuration has two layers: providers decide what is available, and model switches decide what appears in the list. Both are changed in Settings, without editing configuration files.

Providers

Method For Notes
OAuth sign-in Providers that support account authorisation Completed in the browser; the token stays local
API key Providers that issue keys Stored encrypted under ~/.ohpie/
Custom provider OpenAI-compatible endpoints Needs a base URL and model names

Custom providers live in ~/.ohpie/agent/models.json, editable in the models configuration panel or by pasting JSON.

Model switches

A provider can return dozens of models. The switches decide which ones appear in the sidebar and the picker. Unselected models do not disappear — they just stop taking up space.

Default model and reasoning

  • Default model: what a new conversation starts with.
  • Reasoning level: the default effort; lower is faster, higher goes deeper.
  • Changing the model inside a conversation affects that session only.

Available reasoning levels come from the model catalog and differ per model. Switching models resets to that model's supported default.

Refreshing the catalog

Providers add and retire models regularly. Refreshing re-fetches the list and keeps your existing switches; newly discovered models start disabled.

Credentials

Model keys and research database keys are managed separately: models under Settings → Models, research APIs under Settings → Credentials. The latter is picked up automatically by ToolUniverse, BioMCP and w77-nfsc-pipeline.

Proxy

Server-side model and API requests honour HTTP_PROXY, HTTPS_PROXY and NO_PROXY. Set them before launch and keep local addresses (localhost, 127.0.0.1) outside the proxy, or local services will be routed through it.

Cost

OhPie does not bill anything: charges happen at the provider you configured. Usage indicators in Settings reflect what the provider returns and are informational — the provider dashboard is authoritative.

Switching models changes answer style and tool-calling habits. After a critical analysis, re-run the core steps with the new model so the conclusion is not a model artefact.
