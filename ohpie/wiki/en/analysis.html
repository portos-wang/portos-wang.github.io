Analysis and artifacts

A persistent kernel, the notebook standard, publication figures and artifact registration.

Analysis in OhPie is not "here is code, go run it". It runs in a local kernel and leaves the code, the output and the artefacts inside the workspace.

Kernel and environment

  • Python and R use the interpreters already installed on the machine; no bundled runtime.
  • Variables persist across cells and turns: a DataFrame built last turn is still there.
  • A project can point at its own virtual environment or renv, so two studies do not fight over dependencies.
  • A missing environment produces a real error, not a fake success.

The notebook standard

Every analysis produces a pair of files:

.ipynb is for the machine (re-runnable, exportable). .qmd is for the reader (readable, renderable). They carry the same content and are not maintained separately.

Figures

Publication figures follow journal conventions: physical size, type scale, palette and panel labels must survive typesetting. Two actions cover most of it: Nature-standard statistics check (test choice, effect sizes, reporting format) and Journal two-column composite figure (multi-panel layout).

Figures go to experiments/4_results/figures/, tables to tables/. Name files after what they show, not plot1_final_v3.png.

Artifacts and registration

Saved artefacts appear in the artifacts panel and can carry experiment provenance: the code that produced them, the declared inputs, the runtime and a content fingerprint. Those records collect in experiments/4_results/passport.yaml.

Export

  • Notebooks export as .ipynb and .qmd.
  • Tables export as CSV or TSV.
  • Figures export as PNG, PDF or SVG, depending on submission requirements.

Environment setup

When a project needs its own environment, create it inside the project and point at it:

Keep environments out of version control: add .venv/ and renv/library/ to .gitignore and commit requirements.txt / renv.lock instead.

Three ways a study runs

Situation How to ask Where it lands
First look at a dataset “Profile structure, missingness and outliers; do not modify the data” A profiling note in experiments/5_report/
The real analysis “Run this plan; write outputs to 4_results/” Notebook, figures, provenance
A reviewer-requested addition “Add only this subgroup analysis; leave the primary analysis alone” A new numbered notebook, old files untouched

The third rule matters most: new analysis, new file. A reviewer wants to see what changed.

Minimum for a reported statistic

Every number needs an effect size, an uncertainty interval, the sample size and the method. A p value alone will be sent back by most journals.

Element How to report
Effect size Mean difference / HR / OR / β, with units
Uncertainty 95% CI
Sample size n per group, and missingness
Method Test name, and whether multiple comparisons were corrected
Pre-registration State it if it exists; otherwise call the analysis exploratory

Common errors

Error Cause Fix
ModuleNotFoundError: No module named 'pandas' Running on the system interpreter Point the kernel at .venv, or install there
there is no package called 'DESeq2' R package missing BiocManager::install("DESeq2")
Variables gone after a restart The kernel process exited Variables are memory-only; re-run upstream cells
Errors on a non-ASCII path Encoding Use an ASCII path, or set encoding="utf-8"
Chinese labels render as boxes Missing font Use an installed CJK font, or English labels

Figure settings at a glance

Setting Single column Double column Why
Width 85 mm 180 mm Journal layout
Type size 7–8 pt 7–8 pt Legible after scaling
Resolution 300 dpi 300 dpi Minimum for bitmap submission
Line weight 0.5–0.75 pt 0.5–0.75 pt Survives printing
Palette Colour-blind safe, grey-distinguishable Same Print and accessibility

Export vector (PDF/SVG) first; supply 300 dpi+ PNG/TIFF only when the journal demands a bitmap.

Minimum for reproducibility

Four things must exist at once: untouched raw data, cleaning code, analysis code, dependency versions. Lose any one and nobody — including you in six months — can reproduce the result, only redo it.

Running in the kernel is not the same as being correct. Execution, registration and validation are three different facts; see provenance.
