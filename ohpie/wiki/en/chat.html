Conversation and tools

What one turn contains, how much tool permission to grant, and how long threads are compacted.

A prompt is not a single text generation. OhPie shows thinking, tool calls, tool results and the final answer in one stream, so you can see how a number was produced instead of only the claim that follows it.

Inside one turn

  1. Thinking — collapsed by default, expandable.
  2. Tool calls — one card per call, with the tool name, arguments and status.
  3. Tool results — file content, command output, search results; failures are marked as failures.
  4. Writes — changes land in real files in the workspace, where they can be diffed and reverted.
  5. Answer — the part written for you, last.

Referencing files

Typing @ opens the file index and references a file into the current turn. It references the path, not a copy: the model reads the file on disk and edits that same file.

Paths that appear in the conversation are clickable and open in the canvas.

Tool permission

The preset above the composer decides what the agent may touch. More permission means more capability and more risk:

Preset Tools enabled Use it for
Configured Whatever the settings switches allow Fine-grained control
None Nothing Conversation only, no file access
Read only read grep find ls Reviewing, explaining code
Default read bash edit write Day-to-day analysis
Full All of the above plus grep find ls Search and bulk edits

Four request patterns that work

Pattern How to phrase it Why it helps
Name the destination “Write the cleaned data to experiments/2_cleaned_data/” Stops files landing somewhere odd
Plan before execution “Give me the analysis plan first, run it after I confirm” Catches mistakes before they cost tokens
Demand traceability “After each conclusion, name the file and section it came from” Checkable and copyable
Ask for gaps “If something is missing, say so — do not fill it in” More useful than apparent completeness

The anti-pattern is “analyse this data for me”: no variable, no endpoint, no output location, so the result can only be a guess.

Reading tool cards

Tool cards are not decoration. Three things tell you whether the turn is trustworthy:

  • Path — is it the file you expected?
  • Exit status — a failed command invalidates whatever follows it.
  • Truncation — if output was cut, the next inference may rest on half a result.

When something looks wrong, stop and correct it; that is cheaper than cleaning up after a chain of wrong steps.

Models and reasoning

The model picker sets two things at once: which model, and how hard it thinks. Available reasoning levels come from the model catalog, and switching models resets to that model's default level. You can switch mid-conversation — just remember the behaviour changes with it.

Attachments

Images can be pasted or dropped and used to read figures, table screenshots or diagrams. Count and size limits are enforced explicitly: an oversized attachment is rejected rather than silently truncated.

Long conversations

When the context window fills up, the session is compacted into a summary. The full record stays in the .jsonl file, but the model now sees the summary rather than your original wording. If exact phrasing matters, re-reference the file instead of trusting memory.

A failed or interrupted turn offers a retry that reuses the same input. Do not keep appending to a failed turn — retry or stop it first.
