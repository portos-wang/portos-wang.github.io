Canvas and files

Which formats the right panel opens, and which of them refresh on disk changes.

The right panel is not a preview window; it is part of the workbench. It reads real files from the workspace, so the figure you see here is the figure on disk.

Supported formats

Type What you can do
PDF Scroll and zoom; pair with the conversation for page-by-page reading
DOCX Read body and structure, e.g. a manuscript returned by a co-author
Markdown / LaTeX Rendered reading; LaTeX keeps its structure
Jupyter notebooks Cells with code and outputs, long output folded
CSV / TSV Virtualised table view; large files do not render all rows at once
XLSX Read-only worksheet names, without parsing the whole workbook
Images, audio, video Direct preview for checking artefacts
Draw.io Open .drawio / .dio files and edit them in place
Terminal Run commands in the workspace directory
Subagent Read a subagent's full conversation

Tab behaviour

  • The file tree, paths in the conversation and @ results all open tabs.
  • Re-opening a file reuses its tab instead of piling up duplicates.
  • Tabs close and switch normally; content refreshes when the file changes on disk.
  • Artefacts open read-only unless you explicitly ask an editing tool to change them.

Draw.io

.drawio and .dio are editable in the canvas: move nodes, draw connectors, change labels, save back to the original file. Because the artefact is XML, roadmaps and study-design diagrams can live in version control.

Notebooks

.ipynb opens cell by cell — Markdown, code and output (text, table, image) fold separately. In the analysis studio you can keep executing cells, with variables persisting in the kernel.

Terminal

A terminal tab starts in the workspace directory, so git status, file inspection and scripts work immediately. Its environment is isolated from the app's own command environment: host secrets are not passed through.

What opens from where

Starting point Opens
File tree Any previewable file, in a tab
A path in the conversation The same file, positioned in the canvas
An @ reference The file in context; click to open its tab
Artifacts panel Registered figures, tables, reports
Analysis studio .ipynb / .qmd and their outputs
Subagent card That subagent's full transcript

Editing versus read-only

Action Canvas Tools in the conversation
Read a file Yes Yes
Edit text Read-only by default Yes (edit / write)
Save a Draw.io diagram Yes Not recommended
Execute code In the analysis studio Through the kernel tool
Delete a file No Yes, with tool permission

The design intent: the canvas is where you look, edits go through the conversation. That way every write stays in the session record and can be traced later.

Artifacts panel

The artifacts panel collects figures, tables and reports from experiments/4_results/ in one place, grouped by type. It is an index, not a new copy — the files stay in their directories.

The canvas does not tidy files for you. Where an artefact lands depends on what the request (or the skill pack) says — see the workspace.
