Research workflow

Four stages, one return edge, and a provenance record that is not a verdict.

A study in OhPie is a loop rather than a pipeline. Reading changes the analysis, the analysis changes the draft, and the review sends individual claims back to the sources that were supposed to support them.

The four stages

Stage A representative request What lands on disk
Discover “Find primary studies on this question, record the search strategy, and separate full-text evidence from abstract-only findings.” Bibliographic records, screening notes and reading cards in literature/ and notes/.
Analyze “Inspect this dataset, propose an analysis plan, then run the agreed Python or R analysis and save the figures and tables.” Notebooks and scripts in experiments/3_analysis/, clean data in 2_cleaned_data/, outputs in 4_results/.
Draft “Draft this section from the verified evidence and analysis results, and build an editable technical roadmap.” Sections and proposals in manuscript/, Draw.io diagrams in the results directory.
Review “Check whether each citation supports its claim, review the methods, and list the unresolved evidence gaps before revising.” Claim audits, simulated referee reports and revision material.

Review is the return edge

The last stage is not an approval step. A simulated referee report or a claim audit is useful only when it points at a specific sentence, a specific citation and a specific missing condition. When it does, the result is a new search question, which is why the loop closes back on Discover.

This is also why the review packs are written to ask for evidence rather than agreement. A reviewer that only confirms the author's conclusion has produced nothing worth keeping.

The Material Passport

For supported local analyses, OhPie records Experiment Provenance: the archived code, the inputs declared by the analysis, runtime details and a content fingerprint. Those records collect in one file:

The point is falsifiability. A figure with a passport entry can be traced back to the code and the data that produced it; a figure without one is just an image in a folder.

Execution success, recorded provenance and scientific validity are three different facts. A cell can run, a file can be registered, and the conclusion can still be wrong. OhPie records the first two; the third stays with you.

What the workflow deliberately leaves out

OhPie does not decide whether a method is appropriate, whether a sample size is adequate, or whether a journal will accept the result. Those judgements are not tool outputs. The packs are written to expose the gap — a missing control, an unverifiable citation, an overstated claim — rather than to paper over it.
