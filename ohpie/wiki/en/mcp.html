MCP servers

Two scopes, testing, OAuth sign-in, project trust, and how tools are exposed.

MCP is the only way OhPie reaches external tools: literature databases, bioinformatics services, internal systems. The connection is configuration; whether it works depends on reachability and credentials.

Two scopes

Scope File Who uses it
Global ~/.ohpie/mcp.json Every workspace
Project <workspace>/.ohpie/mcp.json This study only

Project definitions win on name collisions. Put study-specific servers in the project scope so switching projects cannot connect to the wrong thing.

Adding a server

  1. Settings → MCP → Add, paste a configuration (common client formats are accepted) or pick stdio / HTTP manually.
  2. Choose the scope, review the parsed result, then save.
  3. Press Test to confirm the connection, the exposed tools and the credentials it needs.
  4. Services that require authorisation use Sign in and complete OAuth in the browser.

stdio servers take command + args + optional env; remote servers take url. The command must resolve from the OhPie process — if the desktop app did not inherit a new PATH, use the absolute path.

How tools are exposed

Declaring every tool of a large service in every turn crowds out the conversation. Two options:

  • deferred — tools are discovered on demand; the model sees the service first and lists tools when needed.
  • code mode — the model writes code that calls tools instead of calling each tool individually.

Both are connection settings, not advanced extras. For a service with more than a dozen tools, start with deferred.

Trust

Project-scoped MCP configuration comes from the repository itself, so it needs a trust decision: opening an unfamiliar workspace does not automatically run the commands in its .ohpie/mcp.json. The decision is remembered per project.

Credentials

  • Service-specific keys go in the connection's env or auth headers.
  • Research database keys go under Settings → Credentials and are picked up by the bundled services.
  • Explicit env values override inherited ones.

Environment variable precedence

Highest first:

  1. An explicit env on the connection
  2. The same-named variable from Settings → Credentials
  3. The application process environment (rarely useful, easily polluted by other software)

When a service reports a wrong key, check in that order.

Error reference

Error Meaning Fix
ENOENT / command not found Command not resolvable Use the absolute path, or fix PATH
ECONNREFUSED HTTP service not running Start the service outside the app first
401 / 403 Missing or expired credential Add env, or sign in again
Empty tool list Service started but registered nothing Read the service's own log and version
Timeout Slow startup or network Raise the timeout, or run it locally

Troubleshooting order

  1. Settings → MCP → Test: does the connection itself work?
  2. Read the error: command not found, timeout, 401 and empty tool list are different problems.
  3. Check the command path and PATH (stdio), or the port and address (HTTP).
  4. Check which layer holds the credential: connection env or global credentials.
  5. Verify with the smallest possible request before asking a complex question.

A successful connection means the handshake worked. Whether the tool can answer your question is up to the service's data and methods — see the boundary notes in Bioinformatics.
