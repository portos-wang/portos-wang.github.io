Extensions and subagents

Installing and updating skills and plugins, both scopes, and how subagents are configured.

Skill packs supply methods and checklists; plugins supply tools and interface extensions. Both are discovered at two scopes, and the project wins on name collisions.

Skills

Action Where Notes
Install Settings → Skills → Install From the skills marketplace or an npm source
Search Settings → Skills → Search Query external skills by keyword
Inspect Skill detail Read the full SKILL.md before trusting it
Update Settings → Skills → Check updates Compares against the source version
Enable / disable Skill list Disabling stops loading; files stay

The 25 bundled packs ship with the application and are seeded into ~/.ohpie/skills/ on first install. They can be overridden: a same-named pack in the project wins.

Plugins

Plugins are npm packages or local extensions that contribute tools. They load on demand and their tools are discovered through tool_search, so they do not sit in every turn.

Keep the distinction straight: builtin-plugins/ ships with the app, ~/.ohpie/plugins/ is what you installed. A packaged install refreshes built-in copies from a recorded baseline while preserving your edits.

Updating

  • Read what changed before updating, especially the method sections of a skill pack.
  • Locally modified skills are merged three ways; conflicts keep the three-way files instead of overwriting.
  • Component version updates go through the maintain flow — see build and maintenance.

Subagents

A subagent takes one self-contained task, runs it in its own session, and returns the result plus its full conversation.

Setting Effect
Built-in subagents toggle Enable or disable the built-in subagents globally
Profiles Preset model, instructions and tool scope per task type
Parent summary The result returns as a card in the main conversation
Full transcript Opened in the canvas

Use one for "read ten papers and tabulate the methodological differences" rather than a long back-and-forth in the main thread. It costs less context and is easier to audit — you can read exactly what it did.

Disabling subagents does not delete existing transcripts. Past records still open; only new subagent sessions stop being created.
