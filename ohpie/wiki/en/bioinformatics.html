Bioinformatics MCP

ToolUniverse and BioMCP run as external MCP services; OhPie supplies the conversation, discovery and file canvas.

OhPie does not embed a bioinformatics pipeline. It calls ToolUniverse and BioMCP through its MCP client, and those services own the databases, the methods, the job state and the answer. OhPie supplies the conversation, tool discovery, connection management and the file canvas that shows what came back.

That boundary is deliberate. When a query returns nothing, the useful question is which service tool ran, with which identifiers and which background — not which local form was filled in incorrectly.

What the Windows installer prepares

Before setup completes, the installer fetches Puppeteer, ToolUniverse and BioMCP plus an isolated Node.js/npm and Python for them. Puppeteer reuses your installed Chrome or Edge and only downloads a browser when none is found. Service environments live in ~/.ohpie/mcp/, retries back off automatically, and failures are logged to install.log in the same directory.

After a fresh install, open Settings → MCP → Global and run Test connection on all three. Upgrades preserve existing configuration, disabled states and recorded removals.

Credentials

Open Settings → Credentials, enter the API keys and contact addresses you need, then Save and sync. The bundled w77-nfsc-pipeline pack, the local ToolUniverse and BioMCP pick these up automatically — no .env editing and no hand-written mcp.json environment block.

PubMed (NCBI), OpenAlex and Semantic Scholar already have entries. For anything else, Add custom credential:

Credential Variables it sets
NCI NCI_API_KEY
DisGeNET DISGENET_API_KEY
UMLS UMLS_API_KEY
OpenFDA OPENFDA_API_KEY
AlphaGenome ALPHAGENOME_API_KEY
OncoKB ONCOKB_TOKEN, ONCOKB_API_KEY
ORCID ORCID_ACCESS_TOKEN

Any other English name generates <NAME>_API_KEY and <NAME>_EMAIL. If a service expects different variable names, fill the optional API key and email variable fields in the same form. Clearing or deleting a credential revokes the corresponding environment variables on the next message.

Explicit env values in an existing MCP entry win over inherited ones. A self-deployed HTTP MCP can reference credential variables in its auth headers, but the databases behind a remote service are that service's responsibility.

Add or customise a server

  1. Install or deploy the service outside OhPie. ToolUniverse documents uvx tooluniverse; BioMCP documents uv tool install biomcp-cli followed by biomcp serve.
  2. Open Settings → MCP → Add, paste the configuration, choose global or project scope, and review the parsed result before saving.
  3. Run Test on each entry to confirm the connection, the tools it exposes and the credentials it needs. Project scope follows the existing trust rules.
  4. Ask for a research task in the conversation. The agent discovers capabilities from the service's current tool schema.

Example requests

  • “Query the ClinVar record for BRAF V600E through BioMCP, list the related studies, and give source links with the scope of what was returned.”
  • “Search ToolUniverse for public datasets on this topic, then list candidate studies with their real file information before anything is downloaded.”
  • “Find enrichment tools in ToolUniverse, check whether the one you pick supports mouse, a custom background and the correction method I need, and only then run it.”

A successful query means that one call returned that result. Empty results, failures, truncation and unknown completeness are reported separately, and methods, species, identifiers, backgrounds and corrections are reported as the service defines them.

What OhPie still does locally

The generic Python/R kernel, notebook export, CSV/TSV tables, XLSX sheet metadata and the artifact canvas keep working on whatever the services save into the workspace. What OhPie no longer provides is the old first-generation pipeline: no built-in count-import, QC/DE/ORA forms, analysis queue or dependency preparation. New analyses use the services' tools and state.

See ADR 0014 for the decision record, and the maintenance page for how the bundled service versions are updated and verified.
