Literature and evidence

Search, screening, close reading, claim-level citation checks and counter-evidence.

The hard part of literature work is not finding papers. It is being able to say which piece of evidence supports which sentence. OhPie splits that chain into actions you can run separately.

Search and sources

Sources arrive through MCP services or API credentials (PubMed, OpenAlex, Semantic Scholar and others). Results are recorded together with the strategy, not just a list of links:

  • query, database, date range
  • hits found and hits kept
  • full text available versus abstract only, marked separately

Screening

PRISMA 2020 double-blind screening runs two screening rounds with recorded exclusion reasons and counts. The output is flowchart data you can put in Methods, not "I read some papers".

Close reading

Three requests you can use today

Copy and adapt them; note that each one names where the output goes:

What an evidence table contains

Column Purpose
Source Authors, year, DOI/PMID
Design Cohort / RCT / cross-sectional / animal / in vitro
Sample Species, n, population
Endpoint Primary endpoint and how it was measured
Result Effect size and interval, not just p
Location Page or figure number for re-checking
Verdict Supports / partial / contrary / unusable

The last column is the point. Without it the table is an extract.

Common misuse

  • Treating abstracts as full text — abstracts drop conditions, so the table systematically overstates.
  • Treating reviews as primary studies — useful for finding papers, not evidence for a result.
  • Only searching for support — a reviewer will supply the counter-evidence for you.
  • Not recording the query — six months later you cannot reproduce what you searched.

Citation checks

Claim-to-citation audit works at the level of the claim: every assertion in the draft is isolated and the cited work is checked for whether it actually supports that sentence, and how far. Three outcomes are normal:

  • supports it (and which part it supports)
  • partially supports it (different conditions, population or endpoint)
  • unresolved (no full text, unreachable source, ambiguous identifier)

The third is not a failure; it is a task list of evidence still to find.

Counter-evidence

Counter-evidence and boundary search looks for opposite results, boundary conditions, alternative explanations and methodological objections. That is more useful for a Discussion section than ten more supporting papers.

Lineage and topic checks

  • Literature lineage: trace predecessors and successors from a seed paper, verifying real citations.
  • Topic overlap check: cross-terminology search for near-identical work.
  • Pre-project evidence assessment / Adversarial idea grilling: question the evidence base before committing.

A successful query is not established evidence. A database returns records, not conclusions; every "supports" has to point somewhere specific.
