Handover and sharing

What to hand to a collaborator, what to archive, and what a reviewer actually needs.

Every study eventually leaves your hands: a collaborator takes over, a supervisor checks it, a reviewer tries to reproduce it, or you reopen it six months later. Whether that works depends on one thing — can the other person redo the work from the workspace alone?

Three deliveries, three scopes

Situation Include Leave out
Same-group handover The whole workspace, including .ohpie/agent/sessions/ Nothing extra
Cross-institution collaboration Workspace plus a handover note and a data inventory Credentials under ~/.ohpie/
Submission supplements figures/ tables/ passport.yaml and code Session records, private raw data

For cross-institution handover, clean ~/.ohpie/ and private session content out first. That is local configuration, not study material.

Sections 2 and 5 are the ones people skip, and the ones that cost the next person the most.

Exporting a session

A single session exports as static HTML with messages, tool calls and results. Use it to answer "how did I arrive at this figure" — not as a data delivery. It is a process record, not data.

Export a session when the reasoning chain matters; hand over the workspace when the work has to run again.

A reviewer's reproduction pack

A reviewer wants to know whether the figure can be rebuilt. The minimum set:

  • Raw data, untouched
  • Cleaning scripts and parameters
  • Analysis scripts or notebooks
  • Dependency manifests (requirements.txt, renv.lock, or equivalent)
  • experiments/4_results/passport.yaml

The passport is what turns "this figure corresponds to which code" into a file instead of an email thread.

What belongs in version control

A workspace can live in Git, but not everything in it should:

Path Suggestion
literature/ experiments/ manuscript/ notes/ Commit
experiments/1_original_data/ Depends on the data agreement; large files go to external storage with recorded fingerprints
.ohpie/agent/sessions/ Depends on content: do not publish if it holds unpublished data or paths
.ohpie/mcp.json May contain service addresses and variable names — review before committing
~/.ohpie/ Never in version control

Read every file under .ohpie/ before making a repository public. Local absolute paths, unpublished results and temporary keys all stay in the JSONL as written.
